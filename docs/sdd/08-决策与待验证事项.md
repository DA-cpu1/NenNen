## 4. 备选处理原则

- eve 若验证不满足本地桌面要求：先记录失败证据、已尝试方案、对体积/恢复/成本的影响。提出在同一 `CompanionRuntime` 接口下改用 AI SDK 的 Agent 运行能力，作为新的决策；本稿未同时批准或实现第二套运行框架。
- 更换运行实现不得改变用户数据归属、人设格式、记忆来源和删除规则。需重跑相关用例。
- 不为了满足某个框架偏好要求所有用户注册额外云账户，或默默将本地架构改为云服务。
- 不因为一个模型不支持工具就把工具假装成功；更换验证过的模型配置。

## 5. 变更流程

小调整（文案、布局、默认尺寸）记录到任务即可。影响范围、人设规则、数据存储或费用的变更记录如下，并同步相关文档：

```text
变更编号与日期：
为什么需要改变（附实测证据）：
原方案 / 新方案：
影响的需求 Rxx：
影响的设计、表、任务、验收：
旧数据怎样保留：
费用、工作量和用户体验影响：
状态：建议 / 已采纳 / 已验证
```

规格、代码、数据库迁移与检查用例一起更新。开发不能只改代码而让文档仍承诺另一种行为。存在争议的产品体验由用户决定，既定范围内的普通实现由开发负责。

### C01 · 2026-10-18：eve 独立服务与内存密钥

- 为什么需要改变：eve 0.80.1 官方自托管方式是 `eve build` 生成独立 Node 服务。当前版本 `@ai-sdk/openai-compatible@3.0.71` 的 `languageModel(id, config)` 第二参数被运行实现忽略，造成请求缺少 Authorization；改用 provider 一级 `apiKey`，在 eve `step.started` 内创建模型后，固定模拟与真实调用均通过。
- 原方案 / 新方案：一个后台承载业务和 eve → 业务后台管理独立 eve 子进程；两跳 stdin 交付机密。带密钥的模型对象仅在执行步骤内存中使用，不写入工作流检查点。
- 影响的需求：R17（按实际执行结果报告）；R03（基础聊天）及后续记忆设计的权威记录仍为 SQLite，产品范围不变。
- 影响的设计、表、任务、验收：03 §3/§4、T01、V02；无需数据库表或迁移变更。新增固定输入进程检查，覆盖端口认证、重启和退出；正式 CompanionRuntime 仍按 04 在后续任务实现。
- 旧数据怎样保留：不读取或修改用户数据库；技术测试每次创建独立的可丢弃运行目录。正式恢复从 SQLite 重建，框架文件不作聊天依据。
- 费用、工作量和体验影响：多一个本机 Node 服务，需要管理端口与孙进程退出。内存占用和安装包体积仍待测。开发启动保留一次固定短消息自测，配密钥会消耗模型用量；本次成功调用两次的 token 和耗时见任务记录，不据此推算人民币价格。
- 状态：**已采纳；本地运行链路已验证**。用户已在本次会话同意执行分步方案及相关文档记录。T01 与 V02 整体尚未完成，不能据此宣称正式会话恢复或安装包通过。
