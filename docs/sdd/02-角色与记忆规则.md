# 02 · 角色与记忆规则

## 1. 角色是怎样维持的

每个角色有一份可编辑、可回退的设定：核心性格、表达习惯、初始关系、背景范围、不同场景的原创示例。每次回复都会带入核心内容。人设修改后新一轮使用新版本，已开始的回复使用开始时的版本。

每个角色有自己的聊天界面、一条持续使用的正式会话和独立历史；再次打开时接续原会话。其他角色的私有对话和记忆不参与当前角色的回复，用户明确指定的共享资料仍按共享范围使用。首版没有新建会话、清空聊天入口，试聊另用 `preview` 会话。

长期记忆不能自动重写核心人设。我们不维护“用户允许什么玩笑”的清单，也不因用户一时不想开玩笑而永久改变角色。模型根据人设、当前情境和明确要求决定表达。

### 角色设定的填写项

| 项目 | 示例意义 |
|---|---|
| 核心性格 | 她在乎什么、如何表达关心、是否习惯嘴硬 |
| 语言习惯 | 句长、词语、比喻、称呼方式；口头禅不是每句必填 |
| 初始关系 | 角色与用户怎样开始相处，可自由填写 |
| 背景边界 | 哪些原作设定沿用、哪些尚未确定，不捏造所谓原作事实 |
| 情境示例 | 同样面对开心、失败、玩笑、严肃倾诉，她怎么回应 |
| 共同原则 | 不编造经历，不用内疚迫使用户继续聊天，工具反馈真实 |

首个角色已由用户于 2026-10-23 确认还原动画版小鸟游六花，与用户已经确定恋人关系；暂不加入具体原作事件，不指定剧情时期（08 D12）。原作资料用于理解角色表达，不把原作人物关系或情节当成与用户的共同经历。正式样稿仍需用户试聊确认；文档示例均为原创设计示例，不冒充原作台词。

### 对话示例

用户：“今天终于把界面弄完了。”

设计示例：“哼哼，今天的结界突破了。最难缠的那一块，也拿下了吗？”

用户：“别开玩笑，我今天真的挺难受。”

设计示例：“……嗯，这次认真听。发生了什么？”

这两句只能说明风格方向，不作为每次照抄的模板。是否像角色，使用 07 中的评价方法检查。

## 2. 记什么、不记什么

| 信息 | 处理 | 原因 |
|---|---|---|
| “以后叫我阿达” | 立即保存称呼要求，不弹窗 | 明确、稳定、后续有用 |
| “最近在做桌面陪伴项目” | 批量保存近期项目背景 | 有来源且能接续话题 |
| “今天加班很累” | 短期状态，默认最多保留 24 小时作为当前状态 | 不能长期把用户当成疲惫 |
| “这周要赶项目” | 默认 7 天后不再视为当前状态；明确日期优先 | 临时安排有时效 |
| “这次就陪我聊聊” | 当前会话背景 | 不能推导出永久拒绝建议 |
| “以后我吐槽先听我讲” | 保存具体互动要求 | 用户明确表达长期意图 |
| 角色说“我们一起去过海边”但用户没说过 | 不存为共同经历 | 模型输出不是用户事实 |
| “假如我不喝咖啡了……” | 不更新饮食偏好 | 假设与事实不同 |
| 转述朋友的话、引用文本 | 不记成用户自身事实 | 说话对象不同 |
| 重复闲聊、寒暄 | 可以不提取 | 记忆不是压缩每一句话 |

对不明确的信息先不保存或只留在当前对话，必要时自然追问实际意思，不能动不动问“是否保存此条记忆”。敏感凭据、临时验证码不作为长期记忆。

有效期是首版可调整默认值；过期信息可作为过去的经历，但不得当成当前状态。未明确结束日期的项目背景不自动宣布“项目结束”。

检索同时检查状态和 `expires_at`，即使旧记录尚未改成 `expired`，也不能作为当前状态返回；历史展示明确注明已过期。写入同一属性的新记忆前，在同一事务中先把已过期旧记录标为 `expired`，避免它仍占用有效记录的唯一位置。

## 3. 三种存储，各司其职

1. **原始聊天：**保存实际说过的话，给用户查看和作为来源。
2. **长期记忆：**挑选的短记录，用于未来相关话题。
3. **对话摘要：**聊天超长时帮助连接较早内容，可重建，不作为新记忆的唯一来源。

第一版先有最近对话和长期记忆；当历史超过上下文预算时，较早原文仍在本地，但不能假装模型始终知道全部历史。第四阶段增加摘要；首版预留来源和失效机制，避免升级时重做数据归属。

完整历史供用户在本地查看，不会每次全部发给模型。每次输入仍按 04 §2 检查起始 12,000 token 总预算及模型实际窗口，优先核心人设和当前消息，再安排相关记忆、近期对话，必要时减少较早对话和示例。单条 8,000 字符是输入长度限制，不等于 token 预算；首版不为超长历史提前增加摘要。

## 4. 自动整理的规则

- 触发起点：累计 10 轮已结束的用户—角色交流，或未处理文本超过 6,000 字符。
- 一轮指一次用户消息及对应回复完整完成；失败、取消不算完成，重试成功后按同一用户消息只计一次，主动消息不计入这 10 轮。
- 会话空闲 5 分钟且有至少 2 条未处理用户消息时，可整理剩余部分；无新消息不运行。
- 一批最多读取 12,000 字符；超长单条按段切分，保留同一个来源消息 ID。具体 token 预算再截断，不跨越被排除的来源。
- 默认每天最多 20 次后台整理、总计 40,000 输入加输出 token；均为起始值，可设置。达到任一上限后延迟任务，聊天继续可用。
- 优先使用服务商返回的实际用量；没有用量时显示“估算”，按保守估算计入限额，不记成零。
- 输出 0～8 条候选项。程序检查来源、归属、重复、过期与冲突；检查通过才写入。
- 一个角色的写入排队执行；用户纠正、忘记优先于后台旧任务。
- 失败最多自动尝试 3 次，间隔约 30 秒、2 分钟、10 分钟；同一批重试不重复写。
- 规则检查只能减少错误，不能证明语义理解一定正确。可查来源、可纠正和质量评测不可省略。

## 5. 使用记忆的规则

- 先限制到当前角色及用户指定的共享资料，再找相关内容。
- 起始上限 8 条，合计最多约 1,500 token；排除已失效、已删除和过期的当前状态。
- 稳定称呼可作为固定偏好带入；其他内容按主题、时间和明确提及程度选择。
- 没找到记忆时正常聊天或承认不记得，不能编造。
- 旧值有历史意义时注明“以前”；对当前事实使用最新有效值。
- 先用中文分词后的词匹配、精确词与时间排序，从已有记忆找出相关内容，再交给模型结合人设回答；不强制每次额外调用模型提炼关键词。
- 以 A10 实测改写问句召回，保留前 8 条中至少 18/20 的门槛。不达标时比较检索改进方案，包括按含义查找的语义检索，在 T07 内改进并重测；不预先锁定新模型或服务，不通过降低分数线解决问题。
- 若采用语义检索，可用可比较的数值寻找意思接近的信息；索引可重建，原始记忆不变。具体实现及费用根据实测再记录到 08。

## 6. 纠正与删除

### 纠正

“我以前喝咖啡，现在不喝了”：新值生效，旧值标为已替代，保留时间关系。旧后台任务不得再次覆盖新值。具体检查见 04、05。

### 忘记一条记忆

删除记忆正文，同时排除与其相关的来源消息，使旧原文不会继续进入模型上下文或再次被提取。首版按整条来源消息排除，可能连同该条消息其他信息一起不再使用；页面提前说明，并允许用户日后重新主动告知。

“忘记”默认不删除聊天列表里的原文，用户仍能查看；页面明确标为“忘记此信息（聊天原文仍保留）”。“同时删除原文”提供单独明确操作。

受影响的待执行整理跳过，调用模型前再次检查版本；已运行任务尝试取消，提交时仍拒绝旧结果，确有需要才按新状态重排。受影响的正在逐字显示的回复停止，已显示部分标为“未完成”，清理旧上下文后才能继续后续回复。旧摘要失效规则预留给第四阶段，首版不生成摘要；Agent 的旧会话缓存必须重建。这些本地失效与清理步骤完成后才报告忘记成功，不依赖服务商是否接受取消。取消不保证已发生的模型用量退回。恢复旧备份会恢复旧数据，恢复前必须说明备份日期及覆盖影响。

### 歧义

“忘掉那件事”若有多个可能对象，问一句具体指哪件事。不能猜着删除整个数据库。

## 7. 主动陪伴

默认关闭；开启后的起始间隔为 120 分钟，默认免打扰 23:00～08:00，以设备所设置的用户时区判断，用户可修改。

1. 定时器只产生一次开口机会。
2. 程序检查免打扰、锁屏、用户最近 15 分钟是否发言、是否有回复进行中、频率上限。
3. 条件通过才调用模型，提供人设、当前时间、最近 3 条主动消息。
4. 模型返回“说一句”或“保持安静”；首版不默认读取整段私人历史作主动话题。
5. 发送前再次检查，避免生成期间用户开始聊天仍弹出。

起始上限每天 6 次模型评估、4 条实际气泡；即使模型多次选择安静，也不能无限调用。一次机会只运行一次。气泡不抢焦点、不自动展开窗口，建议最多 80 个中文字符。

休眠后错过的问候不补发，恢复后重新计算下一次机会。完全退出后不继续后台调用；重启也不集中补发。以上是陪伴问候规则，未来用户明确设置的“到点提醒”另立需求，不能混用。
