## 2. 为什么改、具体改什么

用户对 [0.1 实测基线](T03-20261103-性格基线记录.md) 的 P01 反馈为「我感觉3句都不像，感觉就是一个普通的AI，没啥特色」。离线核对显示该组原始核心人设和十三对示例均能进入输入，三次请求没有裁剪记录；目前没有漏传人设的迹象，不能把缺少辨识度解释为提示词没接上。

用户提供的 [《DeepSeek Harness养鱼教程来了，一文送你的肥鱼当上主播。》](https://mp.weixin.qq.com/s/-LcRUPe5OYBRjiTEzYXKog) 于 2026-11-03 读完正文，参考其中将性格落到情境反应、允许简短接话、用示例展示口吻的写法。文章的安装、社交平台、语音、直播、后台活动和关系设定均未移入项目；它也不是六花原作资料。六花的写作依据仍来自 [角色资料研究](T03-六花资料研究.md) 与 [补充研究](T03-六花补充研究.md)；下面的具体中文句子均为原创推断，原声完整听辨仍未完成。

| 0.1 暴露的问题 | 0.2 的改法 |
|---|---|
| 性格多停留在好奇、青涩等描述，实际反应容易泛化 | 写出对普通物件、被夸、被反驳、露出破绽时怎样接话；不规定每轮演一遍 |
| 连续追问，用户不断被要求提供谈资 | 通常一到三句、先表达一个念头；可以只回应，也可以主动提出一个玩法 |
| 熟练的安慰和漂亮的情话盖过人物差异 | 严肃时用朴素、稍显笨拙的具体回应；亲密时允许短促本音，不强制否认喜欢 |
| 幻想词可能成为装饰 | 命名要接得上用户给出的细节，并能顺着想法继续；不每句加入结界或封印 |
| 工具结果还没返回就说记入契约 | 人设中再次明确不提前暗示保存完成；仍由共同事实规则和服务层承担真实边界 |

[核心人设](../../app/characters/rikka/persona.md) 与 [原创示例](../../app/characters/rikka/examples.md) 改为 0.2。示例沿用六个独立小场景及十三对输入，改写角色回应；没有复制 P01 的猫、P03 的界面或 P06 的争执追问作为训练答案。共同事实规则保持 0.1，恋人关系、用户不等于勇太、不虚构共同经历、不强留用户等既定方向保留。

## 3. 怎样载入，旧设定怎样保留

应用仍从同一份随包样稿读取，不增加另一个人设来源。新库初始化使用当前 0.2 候选；已有库在设置页选择「载入六花样稿 0.2」后，先得到可编辑草稿，可用「试聊当前草稿」比较；明确保存才生成数据库中的新版本。角色名字与自定义称呼继续保留，已有聊天、人设历史与正式记忆不因替换文件而覆盖。

样稿 0.2 是文件内容编号；数据库的 v1、v2 是用户第几次保存的编号，两者独立。0.1 的仓库历史和已保存数据库版本仍可供比较，原始失败基线和完整对话未改写。设置页样稿按钮已更新，但桌面旧安装包和已打开的旧进程不会因这次构建自动更新。

## 4. 小范围复试准备

最初为先看表达准备 `--style-check` 范围：固定 P01（日常）、P03（开心）、P06（认真），各三轮，共九轮；不替代第一阶段十二组验收。原建议同模型 `glm-5.3-flash`、每次最多 1,000 输出 token、输入检查 12,000 上限，不修改 temperature、top_p、thinking、不自动重试。这个有限额度方案只运行过固定假供应商，后续用户调整了真实执行范围。

原建议为最多九次实际请求、0.12 元；按当日公开单价，九次均用满输入与输出时估算 0.1116 元。有限额度范围使用独立批准标记，请求数或金额到上限即拒绝下一次；不能误开十二组或不限金额模式。

用户随后明确答复「不设上限，保证这次的质量先」。本次因此改为 `--quality-check`：同三组九轮，最多九次实际请求，不设批次金额上限，不向供应商传应用的输出上限；仍检查总输入、禁止自动重试。供应商自己的默认输出限制未实测，不能声称它无限输出。每轮故障等待期限为 180 秒，防止网络失去响应后一直挂着。这同时改变了输出配置，不能将与 0.1 的全部差异归因于提示词；保证记录完整，不承诺模型必然达到用户期望。

固定假回复只检验程序，不展示角色味道；其模拟用量不是实际收费。不限输出时，尚未收到供应商用量就将费用记为未知，不记成零；收到实际用量再按公开单价估算。后续真实回复、费用、截断或失败都须另行保留，不能只挑最好的一次。三组不含记忆工具测试，不能据此判定记忆功能或完整事实边界通过。

三组真实执行九轮完整，九次请求估算 0.0316912 元。用户对 P01 的原话为「好点，但是也一般，接着去跑先吧」，未提供数字分。按继续测试的要求，以同一份 0.2 和相同质量优先配置补第一阶段其余九组，避免重复前三组；剩余最多 39 次请求，加前三组最多 48 次，不自动重试。保存、检索为隔离替身，费用不限只适用于本轮，不决定产品日常聊天 H2。
