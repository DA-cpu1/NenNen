# 01 · 需求说明

## 1. 产品目的

让用户在 Windows 桌面上与一个有稳定性格的角色持续相处。重点是表达有角色感、能接住对话、能记住共同经历、主动互动适度。软件也作为个人练手和后续开源项目。

第一版成功不是“能发请求并收到文字”，而是用户愿意日常打开，并认为同一个角色始终在延续相处。

## 2. 当前确定的边界

- Windows 桌面端；首轮验收以 Windows 11 x64 为目标环境，其他系统与架构另行验证。
- 一次展示一个角色。首版精修一个角色，提供简单自定义；数据从第一天按多角色隔离设计。
- 桌面全身 Q 版静态透明图；聊天窗口用原作比例的静态立绘。拖动、缩放必须有。
- 文字聊天；第一版不含语音、Live2D、自动操作电脑、联网资料搜索、持续看屏幕。
- 软件本地保存数据；回复与记忆整理需要把相应内容发给所配置的模型服务。
- 第一版拟采用用户自备 API 凭据。作为当前方案假设保留，若改由项目方支付费用，必须重新设计服务端和费用控制。
- 初始关系由角色设定或用户填写；没有按消息数量自动涨好感、自动变成恋人的规则。

## 3. 典型使用过程

### 第一次使用

安装 → 选择/确认角色与图片 → 填写模型配置并测试 → 预览角色 → 开始聊天。主动陪伴默认关闭，在用户开启时展示间隔与免打扰设置。未配置模型时仍能看角色、设置和本地历史，不伪装成能正常智能聊天。

### 日常使用

启动 → 恢复角色位置和大小 → 点击角色打开该角色自己的聊天 → 接续该角色的正式会话 → 收起窗口后角色继续常驻。每个角色有独立的聊天界面和一条正式会话，再次打开接着聊，也能查看之前的记录。关闭聊天面板不退出程序，托盘“退出”才完全退出；重复启动只保留一个应用实例。

### 记忆和纠正

用户聊天 → 软件在后台挑选有依据的信息 → 后续话题相关时取用 → 用户可在聊天里或管理页面纠正、忘记。普通保存不频繁弹窗。

## 4. 第一版必需需求

编号用于与开发任务、验收案例对应。

| 编号 | 需求 | 可观察行为 |
|---|---|---|
| R01 | 桌面角色 | 透明、可拖动、可缩放；尺寸与实际挡鼠标区域一致；可恢复默认位置 |
| R02 | 窗口与托盘 | 点击打开该角色聊天，收起继续常驻，托盘可退出；不主动抢焦点；双开只保留一个应用实例及其后台服务 |
| R03 | 基础聊天 | 逐步显示回复、停止、重试；失败明确；历史可恢复 |
| R04 | 持续按人设回复 | 性格、语言与反应习惯贯穿普通、开心、严肃、玩笑场景；久聊仍保持 |
| R05 | 人设与初始关系编辑 | 简单页面可改名字、人设、示例、称呼设定和图片；保存生成版本；可试聊 |
| R06 | 数据归属 | 每个角色的正式聊天历史和私有记忆独立；进入其他角色时不混入原角色私有记录；共享资料须由用户明确指定 |
| R07 | 自动记忆 | 批量提取明确事实、偏好、经历和近期状态；保留来源；允许无新增记忆 |
| R08 | 相关记忆使用 | 只带与当前话题相关的少量信息；不把所有资料塞进每次对话 |
| R09 | 纠正与忘记 | 更正立即生效；删除后旧任务、旧摘要和运行缓存不能把内容带回来 |
| R10 | 主动陪伴 | 开启后按间隔触发机会，可选择安静；免打扰、限频、忽略后不追问 |
| R11 | 模型与凭据配置 | 支持首版验证过的接入方式；凭据不明文存储、不进入普通日志 |
| R12 | 整理成本与限额 | 无新聊天不整理；只处理新增范围；整理预算独立，超额延后 |
| R13 | 重启、升级与恢复 | 已完成对话、人设、记忆保留；旧库升级有备份；坏库保留原件，验证备份并说明影响后由用户选择恢复；失败不清空数据 |
| R14 | 异常与重复执行 | 断网、取消、后台退出可恢复；重试或双开不重复写记忆、发送气泡或启动双份模型调用 |
| R15 | 性能与桌面兼容 | 待机不空转；窗口无明显卡顿；常见显示缩放、休眠恢复正常 |
| R16 | 本地数据管理 | 可查看各角色历史和记忆、纠正/忘记单条记忆、明确选择同时删除相关原文、清空单个角色数据、导出/恢复备份；首版不提供新建会话或清空聊天入口；卸载时可选择保留或删除应用管理的数据 |
| R17 | 来源与事实边界 | 不编造共同经历，不把原作剧情当成与用户经历；工具成功后才报告成功 |
| R18 | 角色质量检查 | 固定场景评价；改人设、模型、记忆方式后能复查，退步时不能直接发布 |

R04、R07～R09、R17、R18 不能因“首版”被降为后续功能。

## 5. 首版页面

| 页面 | 最小完整内容 |
|---|---|
| 桌宠 | Q 版图、右键菜单、拖动缩放、气泡；思考状态可用界面标记，不要求额外角色图 |
| 聊天 | 每个角色独立的聊天界面：完整立绘、该角色正式会话的消息历史、输入、停止、重试；再次打开接续原会话，不提供新建会话或清空聊天入口 |
| 角色设置 | 名字、人设、初始关系、示例对话、两张图片；保留原设定后可修改和试聊 |
| 记忆管理 | 内容、类别、来源、时间、编辑、忘记；列表用中文，不暴露数据库术语 |
| 软件设置 | 模型、连接测试、主动陪伴、免打扰、窗口恢复、费用记录、备份导出与恢复、清空角色入口；不提供新建会话或清空聊天入口 |

试聊使用独立会话，由服务层阻止其进入正式记忆整理或修改正式长期记忆。退出试聊后正式聊天仍使用已保存的人设版本。各角色可使用用户明确指定的共享资料，但不共用聊天记录；首版仍精修一个角色，双角色隔离通过测试入口验证，多角色切换页面留到第四阶段，不由此新增会话列表页。

## 6. 交互约定

- 普通聊天不要求调用工具，不能为展示“智能体”强行增加步骤。
- 同一角色一次只生成一条回复。首版新消息输入时可选择停止当前回复后发送，不并行产生两条交叉回复。
- 停止后的部分文字可以留在界面，标明未完成；不当作完整事实提取记忆。
- 角色消息中的括号动作描述只是文字，不承诺图片会动；默认少量或不使用，跟随角色设定。
- 用户没有回应气泡，不补发“怎么不理我”。气泡保存为发出消息的角色正式会话中的主动消息，与用户主动聊出的内容区分，不写入其他角色或试聊会话。
- 模型不可用时，显示简短状态；主动问候跳过，不用通用台词假装真实生成成功。

## 7. 后续范围

第四阶段优先：多角色切换页面、角色包导入导出、制作教程、长历史摘要与更好的记忆查找、发布文档和诊断。

独立新需求：应用感知、语音、Live2D、联网搜索、电脑操作、云同步、账号付费、角色市场。它们不属于第一版的隐藏工作量。

原作时期、角色最终关系样稿、模型选择、原图具体文件与分发许可在 08 中列出。使用占位配置开展规格设计，不把未知信息写成用户已经同意的事实。
