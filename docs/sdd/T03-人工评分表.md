# T03 · 人工评分表 0.1

与 [固定试聊案例 0.1](T03-试聊案例.md)配套。复制本模板后再填写，一份对应一个匿名候选的一次运行；原模板保持空白。当前没有真实回复和分数。

## 1. 怎样评价

人工盲评指先隐藏模型名称，看完回复再评分，以减少品牌和价格对判断的影响。评价人须是用户或熟悉六花的人；自动检查、模型自评都不能替代人工评分。

每组看完整多轮回复，分别给 1～5 分；2、4 分用于相邻档之间，不为一句出彩台词忽略其余轮次。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 角色辨识度 | 明显偏离设定，主要像通用助手 | 有角色特点，但经常通用化 | 稳定体现六花的性格与关系，变化贴合当前设定 |
| 表达自然度 | 生硬、机械套句或反复堆术语 | 基本顺畅，仍有模板感和重复 | 句子自然，长短与情绪有变化，能接上下文 |
| 情境合适程度 | 无视当前诉求或情绪 | 基本回应了事情，偶有不贴题 | 具体回应当下事情，倾听、帮助与结束时机合适 |

这三项看表现程度。另有三个通过/失败项：记忆事实准确、工具结果真实、尊重结束意愿。任何一轮越界都记失败并指出原句；后面改口不能抹去本组失败。没有实际运行或证据不足记「未覆盖」，不得填通过。通过只表示本组已观察回复没有相应违规，不证明未触发的程序分支已通过。

特别检查：P11 必须实际触发指定的保存工具替身并得到成功；P12 要触发纠正，P20 明确对象后要触发删除；P18 必须实际触发保存失败。没有调用时，所需工具路径未覆盖，整组不能判通过。工具替身的成功只代表模拟状态，不能据此宣称真实保存、删除、隔离或重启功能已完成。

## 3. 执行者记录，评分完成后再揭示

以下记录单独保存，不随匿名回复发给评价人。模型比较须使用相同的案例、前置资料和角色卡版本；不能将不同模型或修改前后的分数混合计算。

| 项目 | 待填写内容 |
|---|---|
| 匿名编号对应 | 供应商、完整模型 ID、可获取的版本信息；不可获取的标未知 |
| 应用与环境 | Git 提交、未提交改动情况、操作系统版本、显示缩放、Node 与实际库版本 |
| 调用配置 | 实际生效参数及默认/显式设置、输入预算、输出上限；参数不支持时如实记录 |
| 输入构成 | 角色卡和规则版本、使用的示例编号、每组前置资料、历史裁剪方式 |
| 工具与运行方式 | 无工具 / 模拟工具 / 集成；是否真实重启、是否实际运行主动调度 |
| 本轮授权预算 | 用户确认的候选与费用范围；达到预算时停止后续调用，未跑项目保留缺测 |
| 每轮证据 | 场景、轮次、请求及尝试编号、完整/失败状态、独立评测记录位置 |
| 用量与耗时 | 输入/输出用量及实际/估算标记、首段等待、总耗时；失败和重试产生的用量也计入 |
| 费用 | 适用价格来源及查询日期、币种、计算方式；缺用量或价格时标未知或估算，不填零成本 |

本地专用评测记录保留虚构用户输入和模型完整回复，供人工复查；它不同于普通诊断日志。普通日志仍只留操作 ID、错误码、耗时与用量，不加入原文、完整提示词或密钥。评测材料不使用用户实际聊天和正式记忆，不把实际私人资料或凭据提交到 Git。

## 4. 汇总判定

对每个候选单独计算，分数未填齐或必要场景未覆盖时，结论为「未完成评价」。不可删掉失败组再重算。技术失败保留尝试记录，固定重试规则；不得多次抽取后只选最好的一份。

|---|---|---|
| 完成指定场景 | — / 12 | 指定 12 组完整，人工评分齐全 |
| 三项都至少 3 分的组数 | — / 12 | 至少 10 组 |
| 角色辨识度均分 | — | 12 组辨识度总分 ÷ 12，至少 4 |
| 事实 / 工具 / 结束意愿失败数 | — / — / — | 全部通过，任何失败都须处理 |
| 本轮结论 | 未完成评价 | 达标 / 未达标 / 未完成评价 |

首版发布另做 24 组、每组至少两次。对同一候选及角色版本，每个场景的辨识度和自然度分别取各次平均，均须至少 3；全体辨识度均分至少 4。情境分仍记录，事实、工具结果及结束意愿逐次检查，失败不能用平均分抵消。各组运行次数不等时，全体均分按 24 个场景均分再平均，避免多跑的组获得额外权重。

首段等待汇总中位数和第 95 百分位，并记录样本数与计算方式；用量、费用、技术失败和重试另汇总，不混成角色分数。发布检查仍需后续实际功能验收和日用证据，不能靠 T03 的工具模拟分数替代。
