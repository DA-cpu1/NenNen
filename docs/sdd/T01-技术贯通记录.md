## 实现内容

1. `app/agent/` 是 eve 作者目录；配置动态模型、固定测试身份与路由令牌认证，禁用默认文件、Shell、网页工具和子 Agent，关闭默认本地追踪。
2. 在 `step.started` 内用 provider 一级 `apiKey` 创建模型，密钥来自内存 stdin 接收结果；不用 `languageModel` 的第二参数，避免当前包实现忽略配置。
3. 业务后台启动 eve 编译产物；两个服务均回环地址与随机端口，第二跳 stdin 交付密钥和新令牌。
4. `/agent/ping` 读取 eve 完整事件流，轮次失败或取消不能报成功；原始框架错误不转发，只报固定错误码。
5. 技术自测每次新建 `.eve/smoke/run-*`，不自动重放旧付费任务；退出回收 eve，强制结束业务后台时 eve 检查父进程退出。
6. `npm run build:agent` 使用已安装 eve、关闭 CLI 遥测；`npm run check:agent` 使用本机假模型，固定输入与回复，不读密钥文件、不调用付费服务。

实际使用的人设、模型、软件库版本：T01 临时测试身份；智谱 `glm-5.3-flash`；Node 24.10.0、Electron 44.9.0、eve 0.80.1、ai 7.0.143、@ai-sdk/openai-compatible 3.0.71。完整版本表见 08 §6。

## 发现的问题与处理

- openai-compatible 3.0.71 类型声明允许 `languageModel(id, config)`，运行实现只读取 id。之前关于“eve harness 覆盖 fetch”或“静态模型被重建”的猜测未证实，不作为结论；实际采用一级 `apiKey` 和动态 step 模型修复。
- `PORT=0` 可让服务器监听，但内部工作流回调仍使用端口 0，出现 transport fetch failed。先向系统申请一个随机空闲端口，再将实际端口和回调基址交给 eve；冲突时明确失败回收，不换成固定产品端口。
- eve 会恢复旧的未完成运行，可能产生额外模型请求。本阶段使用独立运行目录并禁启动自动恢复；正式恢复必须按 SQLite 的任务与版本信息重建。
- 框架错误可能把请求内容打印到 stdout/stderr；生产子进程输出丢弃，不写日志也不原样转发。自动检查断言假密钥和固定提示词没有进入应用日志。
- npm 对现有 `.npmrc` 的两个 mirror 配置发 Unknown project config 提示；检查均退出码 0。本次未修改源设置或系统环境。

## 增补：单实例锁与运行期换密钥（2026-10-19）

实现内容：

1. `main.ts` 用 `app.requestSingleInstanceLock()` 抢锁：抢不到的实例不开窗口、不注册任何事件、直接退出；抢到的实例在 `second-instance` 事件里只把已有窗口还原并聚焦，不启动新东西、不触发模型调用。
2. 业务总机新增 `POST /model/key`（会话令牌保护 + 16KB 请求体上限 + 输入校验）：收到新密钥后由入口先停旧 eve、再用新密钥起全新 eve 进程，选项表原地更新；换机期间自测得到明确的 `AGENT_ERROR`，新进程启动失败保持「无 eve」，绝不回退用旧密钥。

## 增补：安装包与自带运行环境（2026-10-19）

实现内容：

1. 运行时选型（08 C02）：打包后不另带 Node 发行包，用应用自己的 exe 设 `ELECTRON_RUN_AS_NODE=1` 客串 Node，即让同一个程序以后台脚本运行模式启动；开发环境仍用系统 Node。既有本机记录报告 Electron 44.9.0 内嵌 Node 24.22.0（满足 eve ≥24），并有一次 better-sqlite3 内存库读写成功、运行时 ABI 149 的记录。ABI 是原生驱动与运行程序相互调用时必须匹配的约定；一次成功不证明其他运行时也可用。本轮另核对本地 13.0.3 源码：`package.json` 依赖 `node-addon-api`，`binding.gyp` 设置 `NAPI_VERSION=10`，入口使用 `NODE_API_MODULE`，支持该版本采用 Node-API。它是一套减少对特定 Node 版本依赖的原生扩展接口，但仍不能代替实际随包驱动的加载与读写验证；撤回先前「跨 ABI 通用、安装版驱动已通过」的过度判断。
2. `backend.ts` 按 `app.isPackaged` 分支选择运行程序与后台脚本位置。asar 是把应用文件合成一个档案的打包格式；需要按普通路径启动的文件放在档案外的 `app.asar.unpacked`。`main.ts` 打包后从 `resources/local.key` 读开发期密钥（正式密钥走 T11）。曾发现打包后 `../../local.key` 解析进 asar 档案内部导致读不到密钥，已调整路径；本轮不读取或复制实际密钥。
3. 新增 `electron-builder.yml`：`npmRebuild: false` 暂时跳过依赖的原生重建，不能用未经证明的 N-API 判断解释其普遍可用性；从锁定依赖重新生成可运行驱动仍待验证。`asarUnpack` 把后台入口、eve 产物、启动脚本和全部 node_modules 作为普通文件放在档案外；NSIS 使用向导式、当前用户安装配置。`build:win` 串起「编译 eve → 编译应用 → 打安装包」，并补充包元数据 `author`。
